# 仿真环境只读保护

`env` 链接提供完整验证环境的访问入口。nsim 启动编译、仿真和所有 pre/post hooks 时，
同时建立操作系统级的源码写保护，子进程继承该限制。无需用户配置链接清单或编写 hook。

保护范围包括本次计划中的验证根、RTL 根，以及这些目录内符号链接指向的外部文件和目录。
允许读取文件、遍历目录和执行程序；禁止向受保护路径创建、覆盖、追加、删除、重命名、建立硬链接
或修改权限。通过 `env/...` 和源码绝对路径访问使用相同限制。产物、日志和结果写到各自工作目录。
需要修改的输入应先复制到工作目录，不应在 `env` 下生成缓存、数据或编译产物。

nsim 不对用户源码执行 `chmod`，不复制整个验证环境，也不改动宿主机的挂载。
只读限制仅适用于 nsim 启动的任务进程。用户的编辑器仍可修改源码；在普通终端直接运行
`echo ... > env/file` 不经过 nsim 保护，因为符号链接本身没有独立的只读权限。

## 执行节点要求

| 系统 | 实现与要求 |
| --- | --- |
| Linux | 执行节点的 PATH 必须能找到 `bwrap`，并允许建立必要的 user/mount/PID namespaces。通过 `--ro-bind` 将源码放入任务私有的只读挂载视图；网络保持可用以访问工具许可证。 |
| macOS | 使用系统 `/usr/bin/sandbox-exec` 的 Seatbelt 写入拒绝规则。外层沙箱可能不允许再次建立 Seatbelt，需要在允许启动它的普通测试/执行进程中运行 nsim。 |
| 其他平台 | 不支持实际执行，明确报错；配置查询与 dry-run 仍可使用。 |

LSF 在真正执行命令的节点建立并检查保护，提交机检测不能代替执行节点的支持。
工具缺失、namespace 被禁用或系统拒绝保护时，不启动用户命令，也不回退为不受保护的执行。
需要由环境管理员提供后端能力；nsim 不自动安装系统包、提权或修改系统配置。
Linux 后端基于 [Bubblewrap 的只读绑定挂载接口](https://github.com/containers/bubblewrap/blob/main/bwrap.xml)。

自动发现外部符号链接目标不依赖 `data`、`cfg` 等目录名。目标不存在、无法读取或指向当前输出目录时
会拒绝执行，避免保护范围缺失或把输出目录纳入只读范围。输入树应在任务执行期间保持稳定。

`commands.json` 的 `read_only_environment` 标记执行所需保护，dry-run 的 `enforced` 始终为 false。
实际执行记录的 `read_only_environment` 保存使用的后端和受保护路径；没有成功建立保护的任务不能
据此宣称运行通过。只读访问控制不代替 filelist/`project.inputs`/submit `files` 的输入哈希与重跑校验。
submit `files` 显式引用的工程外文件和目录也加入执行进程的只读保护；这些输入不能与输出目录重叠。

## 验证边界

本地 macOS 测试执行实际写入尝试，覆盖编译、仿真、四类 hooks、子进程、源码绝对路径、外部符号链接
目标、保留源码权限及可写输出；LSF 流程使用本地进程级测试服务。Linux 命令构造有单元测试，
真实 Linux namespace、LSF 集群和商业 EDA 工具仍需在目标环境验收。
